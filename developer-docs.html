🕷️ Spid3rWeb Developer Documentation

Spid3rWeb is an expressive, full-stack web framework engineered for the Spid3r programming language. Elegant syntax, Active Record ORM, a layout template engine, and a powerful CLI — with zero external dependencies, running natively on Spid3r's VM and AOT compiler.

🗂️

Active Record ORM

Fluent query builder, automatic timestamps, mass-assignment protection via fillable, relationship accessors.

🗄️

Transactional Migrations

Declarative Schema.create(...), migration tracking table, batch rollback, and database seeders.

🧩

SpiderBD Templates

.bd.html templates with layouts, sections, includes, conditionals, loops, and escaped/raw interpolation.

🛣️

Expressive Router

Static & parameterized routes (:id), route groups with prefix inheritance, 405 detection, route listing.

🧅

Middleware Pipeline

Onion-architecture pipeline, global CORS & logging, session auth guards, custom 404/500 error pages.

🔐

Built-in Auth

Native bcrypt hashing, CSPRNG session tokens (sess_…), cookie or Bearer-token sessions.

⚡

Multi-Engine Database

SQLite, PostgreSQL, MySQL, and MariaDB behind one API — selected via SPID3R_DB_DRIVER with dialect-aware DDL and last-id handling.

🪄

Magic CLI

spid3r magic serve / migrate / make:* — scaffolding, migrations, route inspection, test runner.

Getting Started

1. Requirements

  • Spid3r compiler & runtime toolchain (spid3r on PATH, or target/release/spid3r in the language repo)
  • Windows, Linux, or macOS — no other runtime or package manager needed

2. Initialize the database

# Run outstanding migrations (creates users, sessions, products, orders tables)
spid3r magic migrate

# Seed demo data (user ada@example.com + sample products)
spid3r magic db:seed

# Verify migration status
spid3r magic migrate:status

3. Start the development server

spid3r magic serve            # http://localhost:8000
spid3r magic serve --port 8080  # custom port
spid3r magic serve --dry-run  # validate boot without binding

Alternatively run the server entrypoint directly with a port argument:

spid3r run server.matrix 9000
💡 Verify everything works

Run spid3r magic test — it executes all 6 unit suites plus the E2E track and exits 0 only if everything passes. spid3r magic route:list prints the full route table including /cart and /api/v1/status.

4. Manifest (spider.toml)

[package]
name = "spid3r_web"
version = "1.0.0"
entry = "server.matrix"

[dependencies]
# Zero external packages — the Spid3r stdlib provides HTTP/1.1,
# SQLite bindings, bcrypt, JSON, and thread synchronization.

Request Lifecycle

Every HTTP request flows through Application.handle_request() in a fixed, deterministic order:

Raw HTTP req→ Request wrap + session restore→ Static file check→ Global pipeline (CORS)→ Router match / 405 / 404→ Route middleware (auth…)→ Dispatch handler→ Response
  1. Session restore — Auth.clear() resets per-request state; if the request carries a session token (cookie spid3r_session or Authorization: Bearer), Auth.authenticate_token() rehydrates the user from the sessions table.
  2. Static files — for GET requests under /css/, /js/, /assets/, the kernel serves from public/ with correct content-type headers. Paths containing .., backslashes, NUL bytes, or their percent-encoded forms are rejected (path-traversal defense).
  3. Global middleware — the Pipeline runs global_middleware (CORS by default). A middleware may short-circuit by returning a Response; returning null passes through.
  4. Routing — Router.match_route() resolves method + path. If the path matches another verb, a 405 Method Not Allowed is returned with an Allow header. Otherwise a themed 404 page (or JSON for /api/*). /favicon.ico returns 204.
  5. Route middleware — middleware names declared on the route/group (auth, cors, logger) are resolved to instances and run before dispatch.
  6. Dispatch — closures are invoked directly; "Controller@action" strings resolve via call_action(). Unhandled exceptions are caught and rendered as a themed 500 page (JSON for /api/*).
ℹ️ Server binding

app.listen(port) binds 127.0.0.1 via the stdlib tcp_listen + serve_listener with access logging disabled by default. Use a reverse proxy (nginx, caddy) for TLS/production exposure.

The connection is lazy-opened on first use. SQLite additionally initializes:

PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;   // ms — tolerates concurrent writers
💡 One codebase, any engine

Application code (DB.table(...), models, migrations, seeders) is 100% driver-agnostic. The dialect layer compiles id() to SERIAL (pg), INT AUTO_INCREMENT (mysql/mariadb), or INTEGER PRIMARY KEY AUTOINCREMENT (sqlite) automatically, and every value is escaped per engine before interpolation.

New migration classes must be imported and registered in the magic entrypoint (kernel.register_migration(new …)) before they will run. The same applies to new seeders via kernel.register_seeder(fn() { … }).

Routing

Routes are defined in routes/web.matrix (frontend) and routes/api.matrix (JSON API) against the global Route singleton. Route files expose a register_web_routes() / register_api_routes() function that server.matrix (and the magic CLI) call at boot.

Basic routes

import "framework/Router";

Route.get("/", fn(req) { return view("home", map("title", "Welcome")); });
Route.post("/products", fn(req) { /* create */ });
Route.put("/products/:id", handler);
Route.patch("/products/:id", handler);
Route.delete("/products/:id", handler);

Route parameters

Two syntaxes are supported — both populate req.params:

Route.get("/products/:id", fn(req) {
    let id = int(req.param("id"));   // /products/42 → id = 42
});

// Brace syntax is equivalent:
Route.get("/products/{id}/reviews/{reviewId}", handler);

Route groups

Groups apply a prefix and middleware inheritance to nested registrations, then restore prior state:

Route.group(map("prefix", "/api/v1", "middleware", "auth"), fn() {
    Route.get("/dashboard", dashboard_handler);   // → /api/v1/dashboard
});

Groups nest — prefixes concatenate and middleware accumulates.

Fluent route options

add() returns a RouteEntry, so you can chain:

Route.get("/products/create", handler)
     .middleware("auth")      // single name or list
     .name("products.create");   // named route

Controller string dispatch

Route.get("/home", "StoreController@index");
// Requires: Route.register_controller("StoreController", new StoreController());

Matching rules

  • Trailing slashes are normalized on both pattern and request path.
  • Segments must match in count; :param / {param} segments capture any value.
  • If the path exists under other verbs → 405 with Allow: GET, POST, …; else 404 (themed HTML or JSON under /api/).

Controllers

Controllers live in app/Controllers/ and group request handling logic. Instantiate them at the top of your route file and wrap them in closures:

// app/Controllers/ProductController.matrix
import "framework/Response";
import "framework/View/BD";
import "framework/Auth/Auth";
import "framework/Database/DB";
import "app/Models/Product";

public class ProductController {
    fn new() {}

    public fn index(self, _req) {
        let products = DB.table("products")
            .where("stock", ">", 0)
            .orderBy("id", "DESC")
            .get();

        return view("products.index", map(
            "title", "All Products - Spid3rWeb",
            "products", products,
            "is_auth", Auth.check()
        ));
    }
}
ℹ️ Method signature convention

Instance methods take (self, req). When binding routes, wrap with a closure: Route.get("/products", fn(req) { return product_ctrl.index(req); }).

Requests & Validation

framework/Request.matrix wraps the raw server map into a rich Request object. Each handler receives it as req.

Parsing behavior

  • Query strings — parsed from the path (/products?page=2) and/or the server's raw_query, with url_decode applied to keys and values.
  • JSON bodies — via stdlib http_body_json; map keys merged into input data.
  • Form bodies — application/x-www-form-urlencoded (or bare bodies containing =) are parsed as key/value pairs.
  • Headers — normalized to lowercase; access with req.header("content-type").
  • Session token — extracted from Authorization: Bearer <token> first, then the spid3r_session cookie.

Input accessors

req.input(key, default)anybody data → query → route params
req.string(key, default="")stringcoerced via string()
req.int(key, default=0)intcoerced, falls back on parse failure
req.param(key)anyroute parameters only (:id)
req.query(key)anyquery string only

Declarative validation

public fn store(self, req) {
    let validator = req.validate(map(
        "name",    "required|min:3",
        "email",   "required|email",
        "description", "required|min:20",
        "status",  "in:active,archived",
        "password","required|confirmed"
    ));

    if validator.fails() {
        return view("products.create", map("error", validator.error_summary()));
    }
    // …proceed
}

💡 Cookie security

cookie() automatically sets HttpOnly and SameSite=Lax, guarding against JS access and most CSRF vectors. Add res.header("set-cookie", …) chains for multiple cookies.

Default headers

Every response ships with permissive CORS headers: access-control-allow-origin: *, allowed methods, and allowed headers — override per response when locking down.

Middleware

Middleware intercepts requests before route dispatch. The Pipeline runs each pipe's handle(req) in order:

  • Return a Response → short-circuit (pipeline stops, response is sent).
  • Return null → pass through to the next pipe / destination.

Built-in middlewares

ClassBehavior
CorsMiddlewareAnswers OPTIONS preflight with 204 + full CORS headers; passes everything else
LoggerMiddlewarePrints [Spid3rWeb] GET /path to stdout, then passes through
AuthMiddlewareRestores session from token if needed; unauthenticated requests get 401 JSON for API paths (or JSON Accept), otherwise a redirect to /login

Attaching middleware

// Per-route
Route.get("/admin", handler).middleware("auth");

// Per-group (inherited by all nested routes)
Route.group(map("prefix", "/admin", "middleware", "auth"), fn() { … });

// Global — in Application.matrix constructor
self.global_middleware = list(new CorsMiddleware());
app.use(new LoggerMiddleware());   // app.use() is chainable

Named resolution

Route middleware names are resolved by Application.resolve_middleware(): "auth" → AuthMiddleware, "cors" → CorsMiddleware, "logger" → LoggerMiddleware. To register custom middleware, add your own mapping there or push instances directly.

Writing custom middleware

// app/Middleware/RateLimitMiddleware.matrix
public class RateLimitMiddleware {
    fn new() {}
    public fn handle(self, req) {
        // return a Response to block, or null to pass
        return null;
    }
}

Query Builder (DB)

The global DB facade (framework/Database/DB.matrix) is a DatabaseManager singleton. DB.table(name) returns a fluent QueryBuilder; all values are bound as ? parameters (SQL-injection safe for data).

Reading

let products = DB.table("products")
    .select(["id", "name", "price"])   // default: ["*"]
    .where("category", "=", "Electronics")
    .orWhere("sold", ">", 100)
    .orderBy("id", "DESC")
    .limit(10)
    .offset(20)
    .get();                               // → list of row maps

let one   = DB.table("products").where("id", "=", 7).first();  // map or null
let row   = DB.table("products").find(7);                        // where(id).first()
let total = DB.table("products").where("stock", "=", 0).count();

// Debug: inspect compiled SQL and bindings without executing
let sql = DB.table("products").where("id", "=", 1).toSql();
let bnd = DB.table("products").where("id", "=", 1).getBindings();
💡 2-argument where shorthand

.where("id", 5) is sugar for .where("id", "=", 5). Same for orWhere and the join helpers.

Writing

// INSERT — returns last insert id
let id = DB.table("products").insert(map(
    "name", "Wireless Mouse",
    "slug", "wireless-mouse",
    "price", 850
));

// UPDATE — returns number of changed rows
DB.table("products").where("id", "=", id).update(map("price", 799));

// DELETE — returns number of deleted rows
DB.table("products").where("id", "=", id).delete();

Joins

DB.table("products")
  .join("users", "orders.user_id", "=", "users.id")      // INNER
  .leftJoin("payments", "orders.id", "=", "payments.order_id")
  .select(["orders.total", "users.name"])
  .get();
// also: innerJoin, rightJoin, crossJoin(table)

Raw access (DatabaseManager)

DB.connection() # raw handle: .query(sql, params) / .exec(sql) / .run(sql, params) DB.select(sql, params=[]) # rows list DB.statement(sql, params=[]) # DDL / DML DB.table(name) # new QueryBuilder DB.checkpoint() # PRAGMA wal_checkpoint(TRUNCATE) DB.close() # checkpoint, close, remove -shm/-wal artifacts

Active Record Models

Extend Model (from framework/Database/Model). The constructor takes super(table, fillable_list, attrs):

// app/Models/Product.matrix
import "framework/Database/Model";
import "framework/Database/DB";

public class Product extends Model {
    fn new(attrs = null) {
        super("products", ["name", "slug", "description", "price",
                         "category", "stock", "sold"], attrs);
    }

    // Helper: is the product in stock?
    public fn in_stock(self) {
        return self.get("stock", 0) > 0;
    }

    // Static finders
    public static fn find(id) { … }
    public static fn findBySlug(slug) { … }
    public static fn byCategory(category) { … }
    public static fn all() { … }
    public static fn create(attrs) { … }
}

// Backwards-compatible alias
public let ProductModel = Product;

Instance API (inherited from Model)

MethodDescription
get(key, default=null)Attribute accessor
set(key, value)Attribute setter (chainable)
save()Insert or update based on exists; auto-manages created_at/updated_at (unix timestamps)
update(attrs)Mass-update through fillable, then save()

⚠️ Mass-assignment protection

Only keys listed in fillable are written by save() / update(). An empty fillable list allows all keys — always declare it explicitly. The id primary key is never overwritten on update.

Usage

// Create
let product = Product.create(map("name", "New", "price", 500, "stock", 10));

// Find & mutate
let p = Product.find(42);
p.update(map("stock", 25));

// Custom helpers
let available = product.in_stock();

// Backwards-compatible style (pre-2.0 code)
let m = new ProductModel(map("name", "…")); m.save();

Schema Builder

Schema (global singleton in framework/Database/Schema.matrix) compiles blueprints into CREATE TABLE IF NOT EXISTS DDL.

Schema.create("products", table => {
    table.id();                 // INTEGER PRIMARY KEY AUTOINCREMENT
    table.string("name");       // TEXT
    table.string("slug").unique();
    table.text("description");
    table.integer("price");     // INTEGER
    table.float("rating");      // REAL
    table.boolean("is_active"); // INTEGER (0/1)
    table.timestamps();         // created_at TEXT, updated_at TEXT (nullable)
});

Schema.dropIfExists("products");

Column modifiers (chainable)

ModifierSQL effect
.unique()Adds UNIQUE
.nullable()Skips the default NOT NULL
.default(value)Adds DEFAULT 'v' (quoted for strings)
ℹ️ Dialect type mapping

id() → INTEGER PRIMARY KEY AUTOINCREMENT (sqlite) / SERIAL (postgres) / INT AUTO_INCREMENT (mysql) · string → TEXT (sqlite) / VARCHAR(n) (pg/mysql) · float → REAL/DOUBLE PRECISION/DOUBLE · boolean → INTEGER/BOOLEAN/TINYINT(1). Columns are NOT NULL unless marked nullable() or id().

Migrations & Seeders

Migrations live in database/migrations/, numbered NNN_name.matrix. Each extends Migration and implements up() / down():

// database/migrations/004_create_products_table.matrix
import "framework/Database/Schema";
import "framework/Database/Migration";

public class CreateProductsTable extends Migration {
    fn new(name: string = "004_create_products_table") {
        super(name);
    }

    public fn up(self) {
        Schema.create("products", table => { … });
    }
    public fn down(self) {
        Schema.dropIfExists("products");
    }
}

How tracking works

  • The runner ensures a migrations table: id · migration (UNIQUE) · batch · applied_at.
  • migrate runs any un-applied class (by name) and records it under the next batch number.
  • migrate:rollback reverts the entire last batch (calls down() in reverse order) and deletes the tracking rows.
  • migrate:status prints an ASCII table: migration name → Yes (batch) / No.

Seeders

Seeders live in database/seeders/. Define run_database_seeder() and register a closure in the magic entrypoint:

kernel.register_seeder(fn() { run_database_seeder(); });

The bundled DatabaseSeeder creates the demo user ada@example.com (bcrypt-hashed password) and a sample product catalog.

Authentication & Hashing

Auth is a per-request AuthManager singleton (framework/Auth/Auth.matrix); Hash wraps the native bcrypt stdlib.

Credentials

// Verify email+password; on success, logs the user in
if Auth.attempt(email, password) { /* logged in */ }

// Hash a password for storage
let hash = Hash.make("plain-password");      // bcrypt_hash
// Verify
if Hash.check("plain-password", hash) { … }  // bcrypt_verify, error-safe

Session management

MethodDescription
Auth.login(user)Sets current user, generates a CSPRNG token ("sess_" + hex(random_bytes(24)) — 192 bits), inserts a sessions row (token, user_id, last_activity)
Auth.authenticate_token(token)Resolves a session token to a user via users ⨝ sessions
Auth.logout()Deletes the session row and clears state
Auth.check() / Auth.guest()Authenticated? / unauthenticated?
Auth.user() / Auth.id()Current user map / user id (or null)
Auth.token()Current session token string

Token transport

Tokens arrive two ways (checked in order): the Authorization: Bearer <token> header (ideal for API clients) or the spid3r_session cookie (browser sessions). Set the cookie on login:

return redirect("/").cookie("spid3r_session", Auth.token());
ℹ️ Sessions schema

The sessions table (migration 003) stores token TEXT UNIQUE, user_id INTEGER, and last_activity INTEGER (unix). Auth.clear() is invoked at the start of every request so state never leaks between connections.

Caching System

A fluent, expressive Cache facade (framework/Cache/) with swappable store drivers. Selected via SPID3R_CACHE_DRIVER (env or .env); default memory.

Drivers

DriverPersistentShared across processesBest for
memory defaultNoNoPer-request memoization, fastest access
fileYesYes (filesystem)Single-server apps surviving restarts (storage/framework/cache/)
databaseYesYes (SQL)Multi-process/multi-server; works on SQLite, PostgreSQL, MySQL, MariaDB via the DB facade (lazy cache table)

API

// Store & fetch
Cache.put("stats", stats_map, 600);            // 10 minutes (0 = forever)
let stats = Cache.get("stats", null);
Cache.has("stats");  Cache.forget("stats");  Cache.flush();

// Get-or-compute (the workhorse)
let products = Cache.remember("products.catalog", 300, fn() {
    return DB.table("products").where("category", "=", "Electronics").get();
});

// Store only if absent / counters / explicit driver
Cache.add("lock:job", true, 30);
Cache.increment("pageviews");  Cache.decrement("quota", 5);
Cache.store("file").put("key", val, 60);      // target a specific driver

Semantics

  • TTL — seconds > 0 expire after N seconds; 0/null = forever; negative = already expired.
  • Values — strings, numbers, booleans, lists, and maps round-trip via JSON in the file/database drivers. null is always treated as a miss.
  • Expiry — lazy eviction: expired entries are removed on access.
  • remember — returns the cached value on hit; otherwise calls the closure, caches the result, and returns it.
💡 Usage example in a controller
public fn index(self, _req) {
    let products = Cache.remember("products.catalog", 300, fn() {
        return DB.table("products")
            .where("category", "=", "Electronics")
            .orderBy("id", "DESC").get();
    });
    return view("store.index", map("products", products));
}

4. Pagination

public fn index(self, req) {
    let page    = req.int("page", 1);
    let per     = 10;
    let total   = DB.table("products").count();
    let products = DB.table("products")
        .orderBy("id", "DESC")
        .limit(per).offset((page - 1) * per)
        .get();

}

5. Login/logout flow (as implemented in AuthController)

// POST /login
public fn login(self, req) {
    if Auth.attempt(req.string("email"), req.string("password")) {
        return redirect("/").cookie("spid3r_session", Auth.token());
    }
    return view("auth.login", map("error", "Invalid credentials"));
}

// POST /logout
public fn logout(self, req) {
    Auth.logout();
    return redirect("/login").cookie("spid3r_session", "", "/", 0);
}
