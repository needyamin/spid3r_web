4. Unblock / Update Outdated SMTP Error in framework/Mail/Mail.matrix

DONE · P0
spid3r_web/framework/Mail/Mail.matrix:101-103 src/stdlib/net.rs:51-57

Line 102 currently throws: "mail: the smtp driver needs an outbound TCP API that the Spid3r runtime does not expose yet". Spid3r v1.1.1 does expose outbound TCP: tcp_connect(addr), tcp_read(id, max), tcp_write(id, data), tcp_set_timeout(id, ms), and tcp_close(id). You can now implement a real SMTP client for local relays, Mailpit, MailHog, and internal port-25/587 relays.

Honest runtime boundary: src/stdlib/net.rs currently provides server-side TLS (tls_listen / tls_accept), not client-side tls_connect / STARTTLS upgrade. Plain SMTP works now; TLS-enforced external relays (Gmail/SES direct) should either route through a local relay or wait for outbound tls_connect.

5. Replace O(N²) Full-File Log Rewrite with Streaming file_open + file_lock

DONE · P1
spid3r_web/framework/Log/Log.matrix:93-103 src/stdlib/file.rs (Phase R7)

Every single Log.info() / Log.error() currently calls read_file(path) on the entire log file and rewrites existing + line with write_file(). As logs grow to megabytes, every log write becomes O(N) and concurrent processes (server + queue:work) can clobber each other's lines. Spid3r v1.1.1 added real streaming file handles and OS advisory locking: file_open, file_lock, file_write, file_flush, file_unlock, file_close. 

let r = file_open(path, "a");
if r.is_ok() {
    let fh = r.unwrap();
    file_lock(fh, true);
    file_write(fh, line);
    file_flush(fh);
    file_unlock(fh);
    file_close(fh);
}

6. Upgrade LocalDisk.append() to O(1) Streaming Append

DONE · P1
spid3r_web/framework/Filesystem/Storage.matrix:133-145 src/stdlib/file.rs

Just like Log.matrix, LocalDisk.append() reads the whole file into a string and rewrites it. Switching to file_open(path, "a") + file_write + file_close makes appends O(1) and memory-safe for large files.

DONE · P1
spid3r_web/framework/Application.matrix:579-608 stdlib/http.matrix:615-625 (Phase R5)

stdlib/http.matrix's serve_listener() now supports HTTP/1.1 persistent connections (keep_alive default true, idle_timeout_ms backed by spid3r.ini net.keepalive_ms, plus timeout_ms and max_conns). 8. Add Graceful Daemon Mode to Queue.work() with shutdown_requested() & Timers

DONE · P1
spid3r_web/framework/Queue/Queue.matrix:247-257 src/stdlib/shutdown.rs & timer.rs

Queue.work() currently drains existing jobs and exits immediately. With v1.1.1's shutdown_requested() / signal_requested() and after_ms() / every_ms(), magic queue:work --daemon can poll cleanly and exit gracefully on SIGINT/SIGTERM without abandoning in-flight jobs.

9. Add First-Class Native HTTPS Support (app.listen_tls() + magic serve --tls)

DONE · P2
spid3r_web/framework/Application.matrix:579 spid3r_web/framework/Console/ConsoleKernel.matrix stdlib/http.matrix:278,423 (Phase R5)

Spid3r v1.1.1 ships native server-side TLS (tls_listen(cert_path, key_path, addr) + tls_accept) integrated directly into serve_listener(..., map("tls", true), -1). Adding app.listen_tls(port, cert_path, key_path, host) lets Spid3rWeb terminate HTTPS directly without requiring an external reverse proxy in dev or single-binary deployments. 

let r = tls_listen(cert_path, key_path, bind_host + ":" + string(port));
let listener = r.unwrap();
let opts = map("tls", true, "access_log", false, "keep_alive", true);
serve_listener(listener, fn(raw_req) { return app.handle_request(raw_req); }, opts, -1);

10. Add Chunked Streaming & Server-Sent Events (SSE) to Response
